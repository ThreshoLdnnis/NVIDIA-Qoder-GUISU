REFORM / PROJECT PLAN

01项目定位与价值主张

产品叙事同时覆盖公共价值与实际使用场景，长期目标以验证路径支撑。

归塑 ReForm 拟建设一个以 AI 辅助材料理解、循环设计与制造规划的平台。首批服务循环设计师、校园创客和小型再造工坊，将手边不统一的废旧材料整理为可查询的档案，再形成可审阅、可试制的产品方案。

PROBLEM

材料信息难复用

材料尺寸、状态、来源与适用工艺分散；同类物品也可能有不同缺陷与可用程度。

PRODUCT

从材料出发的设计

让库存、尺寸和加工条件成为设计输入，并在条件变化时更新方案与缺口。

PUBLIC VALUE

让再造经验可传递

用透明档案和可复现案例帮助更多人理解材料复用，记录真实用料与制作结果。

需要回答的问题规划中的回答首轮验证方式
谁在何时使用？设计师或创客拿到一批旧材料，准备开展一个具体再造项目时。请 3—5 位目标用户完成材料建档与选方案任务，记录卡点。
提供什么价值？减少整理与反复核对成本，使材料、方案和制作记录保持关联。记录任务完成时间、错误、人工修改和用户解释；先取得基线再比较。
怎样形成可持续业务？先试点材料建档与设计辅助服务，再验证工坊工具订阅；归塑设计品牌承担样品制作与反馈。探索性访谈、试用与付费意愿均记录来源；收入、订单与伙伴按真实进展呈现。

层级本次建议交付展示与证据要求

真实材料案例一批经人工检查的旧木料和金属件，试制可拆装桌面艺术摆件。提供原貌、测量、制作、修改、成品记录；具体形态由实物决定。

03端到端流程与异常处理

每个环节都应能够说明输入、输出、责任人和失败后的去向。选择阶段可查看概要，完整说明保留在下表。

环节输入与输出检查点与异常处理
01 · 材料采集输入：材料实物、多角度照片、来源说明及人工测量。
输出：原始记录与唯一材料编号，保留测量单位和证据文件。		核查材料来源、照片对应关系及测量记录完整性。
来源不明、污染或状态不清时，进入待确认清单，不直接分配给制作任务。
02 · 辅助识别与确认输入：图像、人工填写的尺寸与已有检测资料。
输出：物体类别、可见特征、候选属性与待确认事项。		人工确认后入库；成分、承重等属性需独立依据。
模型不确定或输出不符合结构时，允许人工录入并保留原始结果。
03 · 材料数字入库输入：经确认的材料档案与数量、状态。
输出：可用库存、保留库存、材料护照及版本。		同一属性统一单位；更新有操作记录。
库存不足或已被占用时，明确标出缺口；多人共享时由服务端控制占用。
04 · 需求与候选设计输入：用途、风格、尺寸范围、库存快照、允许工艺。
输出：候选方案、材料引用、设计理由、版本与待验证事项。		候选方案须引用真实材料 ID，保留假设和新增材料。
条件无法满足时返回冲突清单，提出调整需求或补充材料的选项。
05 · 规则与人工审阅输入：设计参数、部件清单、库存与工艺规则。
输出：检查条目、通过/不通过/待核验状态及修改理由。		数量、单位、尺寸分别检查；人工审核记录独立保存。
仅通过数量规则时，只能显示数量满足；涉及结构与工艺的结论等待相应验证。
06 · 制作资料与预演输入：选定设计版本及其部件清单。
输出：结构示意、装配步骤、工具与连接方式、待确认项目。		部件编号、图示、BOM 与步骤保持一致。
原型图示无法支持制作时，返回设计修订；可加工图纸须经工程复核。
07 · 实体试制与记录输入：审核后的制作资料、实际材料与操作人员。
输出：实际用料、余料、工时、问题、修改及成品照片。		先试做一件，记录过程与偏差；库存扣减只随真实使用确认。
发生不适配或制作失败时，暂停该任务，保留原因和相关材料状态。
08 · 反馈、归档与复用输入：试制结果、使用反馈、材料去向和证据。
输出：作品档案、设计新版本、可复用规则与知识条目。		反馈关联到具体版本；人工审核后纳入参考知识。
未经核实的经验保留为观察记录，不直接升级为通用工程结论。

04总体技术架构

架构按体验、编排、智能、数据和工程集成分层；原型不依赖先建成自动化车间。

BROWSER

展示与交互

本次以 HTML / CSS / JavaScript 实现离线可读文档与前端交互。产品原型的材料、清单和图示使用同一结构化数据。

05三个智能引擎与人工复核

AI 负责辅助理解与提案，规则负责可计算检查，工程与实物结论由对应验证过程支撑。

引擎输入输出实现方式与约束
材料智能图像、人工测量、来源、检测记录物体类别、可见特征、候选属性、材料护照图像描述 + 结构化字段；成分、污染及承重等需检测或可靠资料，保留不确定项。
创意智能需求、库存快照、风格、允许工艺候选方案、材料引用、设计理由、BOM 草案模型辅助建议 + 模板参数化 + 规则复核；材料引用和数量由程序校验。
制造智能选定设计、连接方式、工具设备条件步骤、部件关联、待核验清单、制作记录先做装配可视化和试制记录；后续引入 CAD、求解器与设备适配。

专业角色按任务组织：艺术指导负责风格与构图，工业设计负责功能与形态，材料角色检查适用条件，结构与制造角色提出待验证项，成本与可持续角色整理材料去向和费用。每个角色应有明确输入、输出结构和审阅标准。

BEFORE GENERATION

保留真实约束

每次任务记录材料与库存快照、需求版本、可用工艺和新增材料许可。

AFTER GENERATION

执行确定性规则

检查必填字段、材料引用、单位与数量。模型提出的参数保留来源；规则失败列出具体原因。

BEFORE PRODUCTION

保留人工作业入口

工程审阅和实体试制记录独立于生成状态；用户可修改、拒绝或退回候选方案。

多专业工作流可以基于现有模型与工具编排实现。本规划不假定团队已训练专用基础模型，也不把多角色文字输出直接视为跨学科工程验证。

06数据模型与版本追踪

通过关联数据建立可复用知识。初期重点保证一致性、来源和可导出性，再逐步建立检索与知识图谱。

实体关键字段更新规则
MaterialID、来源、类别、尺寸与单位、数量、状态、测量依据、版本。测量与推断分别记录；变更保留前后版本；可用量与保留量分开。
DesignVersion需求快照、材料引用、参数、模型/模板版本、父版本、审阅结果。修改生成新版本；对应 BOM、检查与制作记录锁定同一版本。
DesignMaterial / BOMItem材料 ID、部件 ID、所需数量、单位、连接方式、允许新增项。每一项可追溯；计划用料与实际用料分别保存。
WorkflowTask任务 ID、状态、输入快照、输出、错误类型、请求标识。可重试任务保留关联；重复提交不重复扣库存。
ProductionRecord / Evidence实际耗材、余料、工时、问题、处理结果、照片/录屏来源。试制确认后更新真实库存；证据关联具体对象和版本。

07建议接口与异步任务

接口优先稳定输入输出与错误语义，再选择后端、模型与存储实现；前端示例不依赖这些接口已上线。

方法建议路径处理内容返回与注意事项
POST/api/materials创建材料档案；校验来源、单位、数量与字段。返回材料 ID、版本、待确认项。
PATCH/api/materials/{id}提交预期版本并更新材料。版本冲突返回冲突说明，避免覆盖他人修改。
POST/api/design-jobs提交材料快照、需求、允许工艺及请求标识。返回 job_id 与任务状态；模型调用异步执行。
GET/api/jobs/{id}查询任务的进展和错误。生成失败与待复核分别表示，输出带来源标识。
POST/api/designs/{id}/validate对指定设计版本运行规则。返回逐项 quantity / dimension / process 检查及依据。
POST/api/production-records提交试制用料、问题、图片与设计版本。先验证再确认库存变化，保存审计记录。
GET/api/projects/{id}/export导出项目、材料、设计、检查和证据索引。返回 JSON 或可打印档案，标明未完成事项。

任务状态：queued → running → awaiting_review → succeeded；异常进入 failed 或 cancelled。每次状态变化记录时间、操作者与原因。真实实现可按服务能力简化，但不得用计时动画伪造任务完成。

function checkQuantity(required, available) {
  if (![required, available].every(Number.isInteger) ||
      required < 0 || available < 0) {
    throw new RangeError("数量必须为非负整数");
  }
  const missing = Math.max(0, required - available);
  return { quantitySatisfied: missing === 0, missing };
}

保持数量 3，切换三片构型。所需 3 件，缺口 0；构型与 JSON 同步变化。替代方案引用同一库存状态。
拖动装配步骤，再导出档案。图示按步骤呈现；导出包含材料、构型与检查结果。流程展示与可追溯数据输出。
本示例未调用识别模型、CAD 求解器、物理仿真或真实设备。其用途是为组员展示交互机制和数据一致性要求；真实平台需按后续章节逐项验证。

09工程设计与制造演进

将从视觉概念走向现实制造拆成有明确进入条件的阶段，避免用画面效果替代工程结论。

GATE 01

参数化设计

明确尺寸、部件关系、连接方式和参数范围，输出可编辑几何；图示与参数保持一致。

GATE 02

工程与仿真

收集材料与边界条件，选择适用求解器，记录网格/接触/载荷等设置，使用实物对照校核。

GATE 03

设备映射与试运行

建立坐标标定、工具参数、设备通信与状态反馈，经授权开展限定任务的试运行。

环节进入条件输出与验收门槛
概念 → 工程模型选定设计版本，补齐实测尺寸、连接方式与材料依据。几何可编辑；尺寸、部件、BOM 对应；工程人员审核制作资料。
工程模型 → 仿真确定工况、物理参数、误差范围与求解方法。保留参数、结果与适用边界；建立至少一个实物对照案例。
仿真 → 数字孪生工作单元真实材料、产品、工作站、工序建立对应关系。可追溯设备与场景版本，状态可回传，偏差可记录与分析。
虚拟方案 → 真实设备标定、工具与任务适配通过；执行条件经人员确认。独立安全控制与授权流程；从限定任务试运行到质量检查，保留失败记录。

未来的四类数字对象：Material Twin 保存材料实例与测量属性；Product Twin 保存产品部件与连接；Workcell Twin 保存工作站与设备配置；Process Twin 保存工序、任务与状态。先建立单个案例的映射和校核，再扩大范围。

装配动画、可编辑 CAD、物理仿真与数字孪生分别验收。涉及设备时，急停、限位与防护等控制独立于生成式 AI；本次规划书不执行设备指令。

10环保价值与长期积累

13测试、验收与证据清单

检查目标涵盖工作流、数据一致性、可解释性、媒体访问、异常恢复和真实证据。

技术校验链

  1. 输入检查：必填字段、非负数量、明确单位、材料状态；将模糊描述列为待确认项。
  2. 结构检查：模型响应符合JSON约定；材料ID可追溯，部件引用和需求数量完整。
  3. 约束检查：核对库存、允许新增件、允许工艺及示例模板尺寸条件，逐项解释失败原因。
  4. 一致性检查：材料卡、方案图、部件清单和统计读取同一份数据；输入变更即标记旧报告失效。
  5. 人工复核：对选材、连接和制作步骤留下对应版本的确认记录；实物完成后补录偏差与问题。
验证项目标与记录方式
完整体验新用户无需登录，目标3分钟内完成查看材料、修改约束、查看方案、装配预演与导出；记录实际试用结果。
规则有效性至少覆盖库存充足、库存不足、无效输入与版本变化四类用例，预期结果逐项一致。
数据一致性修改材料后，清单、示意图、统计与JSON同步；导出文件包含当前输入、方案版本和验证状态。
可解释性每个方案提供选材依据、缺口和未确认项；数量校验与工程验证使用不同状态。
异常恢复验证AI超时、服务失败、重试和刷新恢复；预设案例与真实结果来源清晰。
后续模型评测建立经审核的样例集，分别记录类别判断、约束违反、人工修改比例和响应时间；样本量和基线随实测披露。
